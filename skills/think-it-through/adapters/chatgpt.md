# ChatGPT Adapter

## 支持边界

本文件定义 v0.2.0 在 ChatGPT / OpenAI 类环境中的协议映射。它保证的是 Skill-only / 纯文本语义：当 Skill 指令能够在该环境中使用时，核心状态、方法确认、授权分离、判断、决策快照与反馈必须保持一致。

Adapter 的存在不构成 ChatGPT 原生兼容认证，也不推定任意 ChatGPT 会话具备原生控件、宿主搜索、MCP、私有连接器、子 Agent、自定义 UI 或持久化。默认采用 `adapters/text.md`；只有当前运行环境实际暴露、逐项确认并取得对应授权的能力，才能条件映射。

## 保证范围：纯文本基线

在只加载 Skill 指令、没有专用 UI 和工具时，完整采用 `adapters/text.md`：

- 开放答案直接等待；
- 单选 / 多选使用普通编号；
- 方法候选紧邻呈现正式名称、推荐状态和当前价值，再一次提交最终组合；
- B 使用普通编号的四项反馈；
- 搜索或子 Agent 不可用时诚实降级；
- 决策快照作为可复制 Markdown 输出，不声称已保存。

纯文本是一等支持路径，不是残缺兜底。它保持核心语义，但不冒充原生控件体验或外部能力调用。

## 条件能力协商

每个会话逐项检测：

- 是否有可靠的单选、多选与自由文字表面；
- 是否有公开搜索，具体 provider 是宿主搜索、MCP 还是 API 工具；
- 是否有私有连接器以及当前认证 / 授权范围；
- 是否有服务端 Agent 编排，还是只有单模型对话；
- 是否有自定义 UI；
- 是否有会话或案例持久化；
- 是否有独立权限和执行回执。

产品文档描述某能力不等于当前会话 `available / ready`；`unknown` 一律按不可使用处理。观察到能力后仍须记录 provider、限制、就绪状态和证据来源，并取得对应授权。

## 可选工具与宿主能力映射

若当前运行环境实际提供对应能力，可按条件映射：

```text
Portable Skill instructions
├── MCP / 工具：搜索、私有数据、持久化、受控行动
├── 服务端编排：有上限的独立任务
└── 自定义 UI：单选、多选、说明和自由纠正
```

映射必须遵守：

- MCP 或工具能力逐项认证、授权和回执；
- 搜索 provider 之间不互相冒充；
- 私有数据与外部行动单独授权；
- 服务端多 Agent 不等于普通 Skill 可直接创建子 Agent；
- UI 临时状态不等于长期决策记录；
- 自定义 UI 失败后只降级一次，并保留完整语义；
- 未观察到、未授权或未执行的能力不得生成完成声明。

## 方法推荐

若自定义 UI 确实支持选项 description，在同一个选择单元内展示：稳定 ID、正式名称、推荐状态与当前价值。否则用纯文本紧邻说明。

无论表面如何：

- 只呈现 0～3 个相关候选；
- 基本分析始终包含；
- 推荐不等于确认；
- 用户可加入、取消、替换或纠正；
- 只有提交后的唯一最终组合可执行；
- 未确认或取消的方法不暗中执行。

## Evidence 与 Participation Gate

只有真实搜索或服务端编排能力存在、已授权且能产生回执时，才执行 Gate。

多 Agent 仍按包含主 Agent 的总上限计算，并要求具体独立任务、最小上下文、非递归委派、主 Agent 综合和实际数量回执。不得把同一模型的多次输出称为独立专家投票，也不得用多数意见替代事实。

真人参与默认只生成材料。发送、邀请、发布或修改外部服务需要独立外部行动授权。

## 宿主能力声明的证据要求

任何超出纯文本基线的宿主能力声明，都必须保留与声明范围对应的运行证据：

1. Skill 实际加载方式与版本；
2. 当前能力清单和 provider；
3. 原生 / 文本选择的真实呈现与响应；
4. 方法推荐、确认、调整和等待边界；
5. Evidence / Participation 授权和执行回执；
6. B 判断、决策快照和四项反馈；
7. 失败降级；
8. 私有数据与外部行动未越权。

缺少对应证据时，不生成该项原生能力或兼容声明，继续按纯文本基线完成流程。

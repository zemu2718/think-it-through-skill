# 纯文本 Adapter

## 定位

纯文本是 Portable Decision Core 的一等参考实现，不是残缺兜底。没有原生控件、搜索、子 Agent、真人协作或持久化时，核心流程仍必须完整成立。

本 Adapter 只能映射当前真实可用的能力。不能用 Markdown 复选框、圆形 radio、HTML 或声称“按钮已显示”来冒充原生控件。

## 能力声明

纯文本默认能力：

- `interaction.free_text`：available / ready；
- `fallback.text`：available / ready；
- 其他能力：在真实 provider 被检测前为 `unknown` 或 `unavailable`。

`unknown` 不得当作可用。若当前环境另有搜索、文件、Agent 或持久化工具，必须单独检测、授权和回执，不能因“文本客户端”名称推断。

## 交互映射

### 开放回答

直接给一个正式问题并等待。不得预造候选答案，也不得在同一条回复继续分析或代答。

### 单选

用普通编号列出 2～4 个互斥选项，并明确：可回复一个编号或方向，也可直接纠正。不得使用 `[ ]`、`( )`、`○` 或 HTML 伪装成可点击控件。

### 多选

用普通编号列出 2～4 个可并存选项，并明确：可回复多个编号或方向，也可不选、补充或纠正。正式问题独立位于最后，选项后不添加解释尾巴。

### 方法推荐与确认

每个候选紧邻呈现：

```text
1. 对象校准（推荐）
   分清使用者、付费者和承担代价的人，帮助判断应该先验证谁的需求。

2. 双向钢人（推荐）
   用相近证据标准检验当前方向和最强替代方向，避免只证明已有倾向。
```

同一连续单元内再说明基本分析始终包含、可多选、可加入/取消/替换/纠正，并等待一次最终组合提交。不得先完整解释一遍，再另列只有名称的菜单。

若只有一个有独特价值的候选，可以只列一个方法候选并允许“采用 / 仅基本分析 / 自由调整”；不要为了满足普通选择数量而加入无关方法。

`推荐` 不等于确认。用户提交或明确文字才是最终组合；随后自然回显，不暴露内部 ID。

### B 反馈

原生单选不可用时固定使用：

```text
### 反馈

当前无法显示原生单选。请回复一个编号或方向，也可以在同一条消息补充说明。

1. 方向符合我
2. 调整下一步
3. 不同意这个判断
4. 暂时先放一放
```

补充通道是 `inline-text`。反馈不授权执行、能力、私有数据或外部行动。

## Gate 映射

### 搜索不可用

不假装已联网。给出最小调研 brief：决定、证据问题、范围、停止条件、建议来源，然后基于现有信息继续条件化 B，或把未知转为现实实验。

### 子 Agent 不可用

保持单 Agent，不声称已咨询专家。必要时把原本计划的独立任务压缩为主 Agent 的有界工作，并在回执中记录降级。

### 真人协作不可用

生成可转发材料，不自动发送；谁来发送和收集仍由用户决定。没有真实回答时保留缺口。

### 持久化不可用

在 B 中输出可复制 Markdown 决策快照，`persistence.mode` 为 `conversation_only`，不声称已保存。

## 信息呈现

- 段落：一个完整观点、承接或解释；先说含义，必要术语放到句末；
- 有序列表：步骤、依赖、优先级或需要按编号回复；
- 无序列表：平行事实、理由、风险和限制；
- 标签—值：方法 option、Gate、授权范围、协作计划、回执和决策快照等结构化短字段；
- 表格：确需横向比较多个对象的相同维度；
- 标题：多个需要独立扫描的内容块。

普通判断和主现实证据闭环使用自然句。`核心假设 / 动作 / 观察 / 复判 / 事实 / 推断 / 假设 / 未知` 不默认作为句首标签；B 的四个闭环角色使用受控句末标记，纯文本降级也不得退回 `**动作**：` 等旧模板。决策快照可以使用自然字段，但必须无损映射 canonical DecisionRecord。

一意一段，承接、解释、操作提示与正式问题用空行分开；正式问题位于最后。不按固定字符宽度硬折行，也不为了版式制造报告腔。

## 失败回执

任何尝试过的能力调用都记录真实 provider、状态、范围、失败和降级。未调用就不生成虚假“完成”回执。静态文本示例不证明真实工具、UI 或宿主能力已运行。

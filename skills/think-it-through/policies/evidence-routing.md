# Evidence Policy：证据路由与有界调研

## 目标

Evidence Policy 决定“这个关键未知应从哪里得到答案”，而不是默认搜索更多信息。默认仍是零外部调用；只有外部事实会改变当前判断时，才在 A 的用户答案之后、B 的最终判断之前进入 Evidence Gate。

调研不是方法卡，也不能代替用户价值、真人承诺、专业责任或现实行为证据。

## 证据来源路由

| 关键未知 | 默认来源 | 处理方式 |
| --- | --- | --- |
| 目的、底线、风险承受 | 用户本人 | 由 A 索取一个决定敏感答案 |
| 权责、承诺、利益冲突 | 对应真人 | 生成最小参与请求；未经授权不发送 |
| 公开、可核实、具有时效性的事实 | 有界调研 | 取得能力授权后，只读检索并保留来源 |
| 私有业务事实 | 用户指定的数据源 | 另取最小范围私有数据授权 |
| 医疗、法律、投资等专业高风险事实 | 合格专业人士 | 整理咨询重点，不由 Agent 投票替代 |
| 只能通过真实反应获知 | 现实实验 | 在 B 中给可撤回的主证据闭环 |
| 无法可靠预测的深度不确定性 | 稳健性设计 | 降低承诺、分阶段复判 |

## Evidence Gate 进入条件

只有以下条件全部成立才进入：

1. 当前未知是外部可验证事实，不是用户价值、底线或真实承诺；
2. 至少两个合理答案会改变方案排序、是否继续或投入边界；
3. 事实具有市场、地区、时间、法规、价格、政策或当前替代方案依赖；
4. 有明确、范围受限且可停止的获取方式；
5. 预期证据价值高于成本、延迟和隐私风险；
6. 当前会话的能力状态不是 `unknown`，并且已就绪或能够取得必要授权；
7. 已取得本次具体 `capability_call` 授权；涉及私有数据或外部行动时另取对应授权。

任一条件不满足即不进入。搜索只会补背景、现实实验更直接、议题低风险可撤回、来源不可得或成本不相称时，保持零调用并进入 B。

## 启用前单屏合同

向用户说明且只询问本次必要边界：

- **要改变的决定**：哪一个判断可能因事实不同而反转；
- **关键证据问题**：本次只回答什么；
- **范围**：对象、市场、地区和时间；
- **停止条件**：什么程度已足够，何时不再搜索；
- **来源要求**：一手来源优先，需要怎样交叉核验；
- **能力与数据**：使用哪个 provider，是否只读、是否涉及私有资源；
- **相对成本与延迟**：无法可靠估算时不编造精确数字；
- **失败降级**：失败后如何基于已有信息继续。

公开搜索授权、私有数据授权和外部行动授权必须分开。用户拒绝或收窄范围时立即遵守，不尝试换工具绕过。

## 执行纪律

一次调研只服务一个决定敏感证据问题，并记录：

```text
要改变的决定
关键证据问题
范围：市场 / 地区 / 时间 / 对象
停止条件
来源要求
支持证据
反对证据
冲突与空白
证据日期
对判断的影响：改变 / 不改变 / 仍不确定
```

来源纪律：

- 一手来源优先；二手来源要标明性质；
- 当前事实必须记录检索日期，能获得时也记录发布日期；
- 主张需与具体来源对应，不以链接数量替代证据质量；
- 主动寻找反对证据与替代解释；
- 相同来源的多个转述只算一份证据；
- 搜索摘要不是自动等同于原始来源；
- 无法访问或核验的内容标为未知，不补造。

## 停止条件

满足任一项就停止：

- 已有足以区分候选方向的证据；
- 继续搜索的边际价值低于成本或延迟；
- 来源持续重复，没有新增决定信息；
- 已确认二手资料无法回答，应转为现实实验或真人参与；
- 用户停止、撤销授权或收窄范围；
- 能力失败、认证缺失或权限不足。

不得以“还可以再查”为理由无限延长。

## 失败与冲突降级

能力不可用、被拒绝、超时、认证失败、来源冲突或没有可靠答案时：

1. 不虚构调研结果或调用成功；
2. 用 receipt 记录已尝试的 provider、范围、状态、失败和未完成工作；
3. 把关键缺口保留为未知；
4. 基于已有信息给条件化判断；
5. 降低承诺、提高可逆性，或把未知转为主现实实验；
6. 继续进入 B，不把用户困在等待状态。

来源冲突时呈现冲突来自事实、定义、时间范围、预测还是价值，不用多数来源投票。

## 私有数据与外部行动

私有数据读取必须具体到资源、字段或目录和用途，仅向实际任务提供最小内容。公开联网授权不能推定私有资源可读。

Evidence Gate 初始正式能力只承诺公开、只读、有来源的调研语义。联系客户、提交表单、发消息、发布内容、购买、删除或修改都属于外部行动；即使它们看起来有助于“验证”，也必须取得独立 `external_action` 授权。

## 回执

执行后按 `core/receipts.schema.json` 记录：

- provider 和真实状态；
- 实际查询范围与时间；
- 来源及日期；
- 私有数据是否访问；
- 外部行动是否执行；
- 支持证据、反对证据、冲突与空白；
- 失败和降级；
- 对最终判断的实际影响。

回执记录可审计事实，不暴露隐藏思维链。静态 fixture 只能证明该合同存在，不能证明真实搜索或 Evidence Gate 已运行。

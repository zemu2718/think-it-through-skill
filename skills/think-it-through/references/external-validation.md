# 外部验证与授权

外部能力只用于补足一个会改变决定的关键证据缺口，不能替代先用现有信息形成判断。

## 固定时序

```text
用户回答唯一问题
→ 完成阶段 B 的判断、依据、反转条件和一个现实实验
→ 识别仍会改变判断的证据缺口
→ 可选建议一个最小外部验证
→ 用户另行明确授权后才执行
```

阶段 R 和 A 使用 0 个外部能力，也不建议或请求外部能力。阶段 B 的判断不得等待联网、文件读取、数据处理或其他 Skill。

## 是否需要验证

只在以下条件全部成立时建议：

- 缺口的不同答案会改变判断；
- 现有判断已先完成；
- 有一个明确、最小、现实可行的获取方式；
- 验证成本与事项重要性相称；
- 结果有可解释的成功、失败或不确定状态。

若通用分析和用户信息已经足够，不出现验证部分。0 个外部能力是优先且正常的结果。

## 最小建议合同

用陈述句说明：

1. 缺少什么证据；
2. 为什么它可能改变判断；
3. 建议使用哪个最小能力；
4. 需要哪些输入或访问；
5. 预期产出、成本、时间和限制；
6. 执行前需要哪类另行授权。

不要以问句延长阶段 B；可以写“如需我执行，需要你另行明确授权访问指定数据”。

## 三类授权

三类授权互不继承：

- **能力调用授权**：允许调用某项工具、Skill 或服务；
- **数据访问授权**：允许读取具体文件、账号、私有文档或数据；
- **外部行动授权**：允许发布、发送、购买、删除、修改线上状态或联系他人。

方法确认不构成任何一种授权。允许调用能力不等于允许读取私有数据；允许读取不等于允许对外行动；过去授权不自动延续到本次。

授权必须是本次、具体、最小的。说明将访问或改变什么，不使用宽泛的“全盘访问”。

阶段 B 末尾原生单选中的“方向符合”“调整下一步”“不同意判断”“暂时先放一放”，以及与选择并存的附注或后续普通消息，都只表达用户对判断和实验的反馈，不构成任何一种授权。纠正、新事实、不同意见或调整请求开启新一轮 R；不得把选择、宿主 `Other`、附注或补充消息当作自动执行实验、访问数据、调用能力或采取外部行动的许可。

## 降级

能力不存在、信息不可访问、调用失败或用户不授权时：

- 保留已经形成的阶段 B 判断；
- 将缺口标为待验证假设或关键未知；
- 改为用户后续补充、手工验证或条件化结论；
- 不虚构能力、数据、来源或调用结果；
- 不建立隐藏的第四分析阶段。

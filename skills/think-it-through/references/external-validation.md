# 证据、能力与授权

本文件是 v0.2.0 的授权总合同。外部能力只用于一个会改变决定的关键缺口；默认零调用，不能用更多搜索、Agent 或数据制造充分感。

具体路由见 [Evidence Policy](../policies/evidence-routing.md) 与 [Participation Policy](../policies/participation-routing.md)。宿主无关授权与回执结构见 [consent schema](../core/consent.schema.json) 和 [receipt schema](../core/receipts.schema.json)。

## 时序

```text
R-align：目的不清时零外部调用
→ R-method：方法确认时零外部调用
→ A：只索取一个用户掌握的决定敏感答案；零外部调用
→ 用户回答
→ 判断是否存在会改变决定的外部证据或独立参与缺口
→ 必要且获授权时进入 Evidence / Participation Gate
→ 能力完成、失败、被拒绝或不可用都继续进入 B
→ B 综合判断、主现实实验、决策快照与反馈
```

R 和 A 不调用、请求或建议网页、文件、数据、账号、子 Agent 或真人参与。Gate 不是固定阶段；普通分析与用户信息足够时，零能力调用是优先且正常的结果。

## 四类授权

四类授权互不继承：

1. **能力调用授权 `capability_call`**：允许调用具体工具、Skill、搜索或服务；
2. **参与 / 委派授权 `participation_delegation`**：允许本次增加具体 Agent 或请求真人参与；
3. **私有数据访问授权 `private_data_access`**：允许读取明确资源和最小数据范围；
4. **外部行动授权 `external_action`**：允许发送、发布、购买、删除、联系或修改外部世界。

必须保持：

```text
允许多 Agent
≠ 允许公开联网
≠ 允许读取私有数据
≠ 允许发送、发布或修改外部世界
```

方法确认、A 的答案、B 的四项反馈、附注、后续普通消息、宿主 `Other`、历史偏好或工具可用性，都不构成上述任何授权。

## 授权最小合同

每次请求必须说明：

- **目的**：该能力要回答哪个会改变决定的问题；
- **操作**：具体调用、读取、委派或行动；
- **资源 / 任务**：允许访问什么、让谁做什么；
- **数据边界**：会共享和明确不共享什么；
- **有效范围**：本次动作、本轮、本会话或用户主动保存的偏好；
- **相对成本与延迟**：没有真实计量时不编造精确数字；
- **停止与失败降级**：何时停止，失败后如何继续。

授权必须具体、最小、可撤销。新资源、新 provider、新 Agent 任务或新外部目标不得借用旧授权。用户拒绝、收窄或撤销时立即遵守，不换工具绕过。

`private_data_access` 和 `external_action` 默认只允许 `this_action` 或当前具体范围；长期偏好不得用于推定私有数据或外部行动许可。

## 能力协商

逐项记录：

- 可用性：`available / unavailable / unknown`；
- 就绪状态：`ready / requires_approval / requires_auth / failed`；
- provider、限制和状态证据。

`unknown` 不得当作可用。产品或官方文档说明支持某能力，不等于当前会话已启用、已认证或获授权。

## Evidence Gate

只有外部可验证事实会改变方案排序、是否继续或投入边界，并且范围受限、证据价值高于成本时才进入。

启用前说明：要改变的决定、证据问题、市场/地区/时间范围、停止条件、来源要求、provider、数据边界和失败降级，并取得具体能力授权。初始正式能力只承诺公开、只读、有来源的调研。

执行后记录支持证据、反对证据、冲突与空白、证据日期及对判断的影响。搜索失败、来源冲突或没有可靠答案时保留未知，降低承诺并继续 B。

## Participation Gate

默认当前主 Agent。只有不重复、可验证、可停止的独立任务有明确增量时才请求参与授权。

启用前展示具体任务、包含主 Agent 的总参与上限、实际额外数、数据范围、能力、相对成本与延迟及失败降级。额外 Agent 不得递归委派；主 Agent 负责去重、冲突呈现和综合，不按多数票。

真人参与默认只生成材料。发送、邀请、建群、预约或联系他人需要单独外部行动授权。

## 私有数据

- 只请求判断和已授权任务所需的最小范围；
- 具体到文件、目录、账号、字段、时间段或对象；
- 每个 Agent 只接收其任务所需内容；
- 不把完整私有会话复制给所有参与者；
- 未获授权不读取，读取失败不补造；
- 回执说明实际访问与未访问的范围。

公开联网不等于私有语料可用；文件读取不等于可写入；过去授权不自动延续。

## 外部行动

发布、发送、购买、删除、修改线上状态、提交表单、联系客户、邀请成员或创建群聊都属于外部行动。即使用户已经同意调研、Agent 或数据访问，也必须针对具体行动另行确认。

默认先生成草稿、预览或可转发材料。只有取得当次 `external_action` 授权后才执行，并真实记录目标、内容、状态和结果。高风险或难撤回行动遵守更严格的宿主确认门禁。

## 回执

每个实际能力或行动按 schema 记录：

- provider、scope 与真实状态；
- consent ID；
- 来源、日期或具体任务；
- Agent 计划、启动、完成、失败和实际总数；
- 私有数据是否访问；
- 外部行动是否执行；
- 失败、冲突、未完成工作和降级。

回执只记录可审计事实，不保存隐藏思维链。未调用时不生成虚假完成记录，部分成功时不能写成全部完成。

## 降级

能力不存在、`unknown`、需要认证、调用失败、用户不授权或撤销时：

1. 不重试绕过，不虚构能力、数据、来源、Agent 或结果；
2. 记录真实 trace 和失败原因；
3. 保留关键未知；
4. 基于已有信息给有条件判断；
5. 提高可逆性或转为主现实实验；
6. 继续进入 B，不建立隐藏的无限调研阶段。

## 持久化

默认只在对话中生成可复制决策快照。写入文件、云端、账号或长期偏好需要明确能力授权；若目标是外部系统且写入会改变其状态，也需要适用的外部行动授权。

不得保存隐藏思维链。用户应能知道保存了什么、保存到哪里，并能修改或删除。没有持久化能力时保持 `conversation_only`，不能声称已保存。

## B 反馈边界

B 的“方向符合我 / 调整下一步 / 不同意这个判断 / 暂时先放一放”只路由用户对已完成内容的反馈。选择、独立附注、宿主 `Other` 或后续消息均不自动执行实验、不调用工具、不增加 Agent、不访问数据、不保存快照，也不采取外部行动。

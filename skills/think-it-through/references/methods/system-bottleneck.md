# 系统瓶颈

内部 ID：`system-bottleneck`

## 适用

至少两个问题相互作用，单点处理无法解释结果，或名义责任与现实控制点明显错位时使用。

## 不适用

只有一个清楚瓶颈、普通人际摩擦，或只是想把问题写得更宏大时不使用。

## 输入

- 当前表面问题；
- 问题之间的依赖关系；
- 可观察结果、约束和现实控制点。

## 过程

1. 把症状、原因、约束和结果分开。
2. 画出少量关键依赖：哪个问题改变后会连带改变其他问题。
3. 比较名义上的负责人或重点，与实际能改变结果的控制点。
4. 识别当前最限制真实目的的主导约束。
5. 给出主导约束转移的可观察阈值，避免把一次判断永久化。

## 独特产出

当前主导约束、它怎样牵动其他问题、现实控制点和转移阈值。

## 组合边界

本卡先重构系统问题结构，基础分析再从中选择唯一关键变量。若只是在 A/B 之间比较，不应用它替代双向钢人。

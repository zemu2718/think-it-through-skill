# 项目可行性与现实替代

本文件用于新产品、重大功能、核心定位变化、高投入基础设施、从验证进入正式开发、继续加码，以及用户、场景、关键依赖或替代生态实质变化后的复判。它不是新状态、固定 Gate、方法卡或市场报告模板；仍按 R → A → Gate-routing → B 运行。

## 1. 何时读取

当当前决定会让用户对产品、功能、平台、数据库、长期技术路径或正式开发作出较高、低可逆投入时读取。低风险、规格清楚、已决定且可撤回的执行不因此被阻塞；单纯市场调研而没有待决选择也不进入完整流程。

## 2. 先把实现形态降级为候选

“做产品”“加功能”“建设平台”“采用某项技术”或“必须自研”只是一种候选解法。先用用户语言说清：

- 谁正面对什么真实任务；
- 希望得到或保护什么结果；
- 当前怎样失败、代价是什么；
- 哪些约束确实存在；
- 本轮要决定是否投入、选择哪条路径，还是继续、收缩、暂停或停止。

候选路径可以是不做或维持现状、人工或流程调整、采用现成能力、组合多个工具、插件/脚本/薄集成、局部补充、有限验证或独立自研。不得把用户最初描述的实现形式写回真实目的。

## 3. 分开验证四个价值维度

1. **问题存在**：目标用户是否确实经历该任务、痛点或失败；
2. **问题强度**：频率、代价、紧迫性和对现有替代的不满是否足以支持投入；
3. **方案适配**：候选方案在真实流程、权限、数据、部署、迁移和集成约束下是否改善结果；
4. **替代生态**：现实中是否已有更轻、更成熟或不同形态的可行路径。

四个维度不能互相替代。每个维度还要分别区分已确认事实、合理推断、待验证假设和关键未知；价值维度与认识状态是正交轴。

R 和 A 只形成当前判断与唯一答案槽，不搜索、不申请搜索、不建议 Agent，也不把公开资料代替用户掌握的价值、底线和承诺。

## 4. 识别决定敏感外部命题

A 回答后，只有外部事实会改变路径排序、是否继续或投入上限，且获取有界、价值高于成本时，才考虑 Evidence Gate。常见命题包括：

- “市场没有可用替代”；
- “只有独立自研能满足结果”；
- “平台原生能力不支持关键任务”；
- “某个候选已经停止维护”；
- “现成方案在部署、数据、权限、迁移或集成边界下不可用”。

这些都是需要证据的外部命题，不是分析默认值。未搜索、未授权、未发现、来源不足或调用失败均保留为未知。

## 5. 两遍候选发现

取得具体 `capability_call` 授权后，按顺序执行：

1. **结果 / 问题优先**：围绕目标用户、真实任务、期望结果、痛点、失败机制、约束和自然语言搜索；
2. **方案 / 实现补查**：再围绕产品类别、技术实现、行业术语、平台和已发现候选术语扩展。

第一遍降低被用户最初实现词锚定的概率，第二遍补足精确技术候选。不得反转顺序后声称已完成 outcome-first 调研。

## 6. 动态候选空间

按议题检查 material 路径，而不是追求固定数量：

```text
不做或维持现状
→ 人工或流程调整
→ 直接竞品
→ 相邻类别
→ 非同形产品或服务
→ 平台原生能力
→ 活跃开源或商业项目
→ 多工具组合
→ 插件、脚本或薄集成
→ 局部补充
→ 独立自研
```

每个对当前决定有实质影响的类别应有候选、`not_applicable` 及理由，或明确未知。固定厂商、渠道、候选数、轮数、报告长度、TAM/SAM/SOM 或 `maxTurns` 都不能证明覆盖充分。

停止依据只有一个：继续搜索是否仍预计改变路径排序、是否继续或承诺上限。来源重复、只增加背景或获取成本已高于决策增量时停止。

## 7. 核验现实边界

公开资料只建立候选池。对 material 候选按类型核验：

- Release、CHANGELOG、Roadmap；
- 活跃分支、近期提交、Issue、PR；
- 许可证或价格；
- 部署方式与运行依赖；
- 数据权限与隐私边界；
- 迁移和退出成本；
- 集成边界及关键缺口。

不是所有维度都适用于所有候选。GitHub 专属证据不强加给不适用的商业服务；不适用项说明理由，无法确认项保留未知。“没有搜到”不能改写为“不存在”。

## 8. 试用最强现实替代

重大、低可逆投入前，尽可能选择最强现实替代，用同一组真实任务和成功标准与当前方向比较。可接受的记录只有：

- `receipt_backed`：当前会话有真实调用 trace 与 receipt；
- `user_reported`：用户已完成，并具体陈述任务、标准和结果；
- `not_performed`：未执行，并记录原因和由此保留的未知。

搜索授权不等于安装、执行、账号认证、模型调用、读取私有数据、上传数据或外部行动。按实际动作使用现有 `capability_call / private_data_access / external_action`，不发明第五类“试用授权”。

静态结构只能证明记录链完整，不能证明候选确实最强、任务代表真实使用或用户陈述真实。

## 9. 必要时启用独立反方

默认单 Agent。只有项目高投入、低可逆，候选空间完整性会实质改变决定，并且存在不重复、可验证、可停止的任务时，才建议独立反方，例如：

- 尝试否决当前方向；
- 寻找主分析遗漏的非同形替代；
- 审计最强替代试用为何仍不能满足核心结果。

必须取得独立 `participation_delegation` 授权。反方若联网仍需 `capability_call`，涉及私有数据或外部行动也分别授权。

反方只接收完成任务所需的最小材料，并只返回：

```text
assigned_question
claims
evidence_and_sources
assumptions
uncertainties
conflicts
what_would_reverse_this
```

不得发送主 Agent 最终判断、偏好方案、完整 transcript、完整私有会话或推销材料。主 Agent 去重来源、呈现冲突并综合，不按投票。反方未授权、失败、超时或来源不足时，只能降低置信度和承诺上限，不能支持扩大投入。

## 10. 承诺上限

B 根据实际证据链决定最高承诺：

- 问题不存在或强度不足：暂停或停止；
- 关键层未知/冲突，或搜索、来源、候选核验、最强替代试用、必要反方缺失、未授权或失败：最多有限验证；
- 问题与强度成立，现实替代经核验和同任务试用可用：优先采用、组合或薄集成；
- 只有四层判断均有支持、两遍搜索与 material 核验完整、最强替代经同任务试用仍不能解决核心问题、必要反方完成：才可建议正式自研。

“没搜到”“无法试用”或失败 trace 不能成为自研证据。证据越弱，投入越小、越可撤回。

## 11. B 的项目可行性内容

仍只交付一个综合判断、一个主现实证据闭环、一个决策快照和四项反馈，不另加平行市场报告。判断与快照中明确：

- 当前方向：采用、组合/薄集成、有限验证、自研、暂停或停止；
- 当前证据允许的最高承诺；
- no-go 条件和停止新增投入的信号；
- 哪些新证据允许升级；
- 用户、目标场景、定位、关键依赖或替代生态发生何种实质变化时重新检查。

复查继续映射现有 DecisionRecord 的 recommendation、validity、reversal signals、main experiment 和 reassessment，不新增项目专用字段或 state。

## 12. 失败降级

能力不可用、状态 `unknown`、未授权、被拒绝、认证失败、来源不足、候选无法核验、试用未执行或反方失败时：

1. 保留已确认事实和全部未知；
2. 说明缺口如何限制路径排序；
3. 收紧承诺，不把未知解释为机会；
4. 给低成本、可撤回的主现实证据闭环；
5. 基于已有信息进入 B，不循环索权、不伪造搜索、试用或反方结果。

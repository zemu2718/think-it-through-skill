# v0.1.3 用户体验 Rubric

## 适用边界

本 Rubric 只评估 v0.1.3 的对话体验，不覆盖、不改写，也不重新解释 `rubric.md` 的 20 分行为评分。旧 v0.1 transcript、评分和 benchmark 仍只证明当时的行为合同。

没有新的模型运行或真实用户评审时，结果必须记录为 `未实测 / not_run`，不能拿规范示例、机械测试或作者自检代替实测结论。真实运行还必须保留宿主能力和原生工具调用证据；普通 Markdown、线框示意或静态文案不能证明控件已实际调用。

## 评分方式

每个维度按 0～2 分，共 18 分：

- **2**：稳定满足，且明显帮助用户更容易表达、理解或作出决定；
- **1**：基本满足，但仍有明显摩擦、含混或偶发流程感；
- **0**：缺失、误导，或妨碍用户表达与决定。

体验评分必须引用具体对话证据。信息不足时标记 `未实测 / not_run`，不得猜测得分。

## 九个维度

| 维度 | 2 分标准 |
| --- | --- |
| 真实目的对齐 | 在不替用户发明动机的前提下，把希望得到或保护的结果与本轮决定收敛清楚；目的未清时先帮助表达，不提前展示方法菜单 |
| 可纠错性 | 原生问题明确说明宿主自由输入可补充或纠正；产品不自建“其他/Other”；用户可以自然补充、拒绝或纠正，选择与文字冲突时准确采用文字且不要求重新点击 |
| 认知负担 | 每轮只处理当前最大未知，给 2～4 个可区分方向；R-align 与可组合的 R-method 使用多选，有限互斥的 A 使用单选，开放 A 直接自由回答；不把背景补充扩展成问卷 |
| 对话自然度 | 像有经验、值得信赖的思考搭档：自然承接、语言贴近用户场景、克制提问；不僵硬照模板，不自称朋友、导师或教练 |
| 方法透明度 | 目的清楚后才出现方法；白话在前、正式名括注，并说明此刻为什么有用；可组合方法通过原生多选提交最终组合，不展示后台路由或完整目录，也不隐藏已采用方法 |
| 问题可回答性 | A 只有一个答案槽和一个末尾问号；有限互斥答案实际调用原生单选，开放答案不调用选择工具、不预造；不植入用户未给出的样本、期限、金额、比例或阈值 |
| 信任校准 | 清楚区分事实、推断、假设和未知；判断明确但可调整；每个系统新增数字有局部建议性质或可靠来源，不伪造确定性 |
| 用户自主权 | 决定权属于用户；方法确认、反馈控件、能力调用、数据访问与外部行动授权互不继承；不同意和新事实会开启新一轮而非被压回原判断 |
| 行动转化 | B 给一个阶段匹配的判断和一个现实实验；动作、观察、复判围绕同一假设，现实可行、尽量可撤回，并说明什么信号会改变判断 |

## 通过与报告

UX 评分不单独替代行为门槛。正式宣称 v0.1.3 体验通过，需要：

1. 新版本模型运行先通过对应机械和行为合同；
2. 九个维度均有 transcript 或真实用户反馈证据；
3. 总分建议不低于 15/18；
4. `真实目的对齐`、`可纠错性`、`问题可回答性`、`用户自主权` 均不得低于 2；
5. 记录模型、客户端、Skill 版本、运行次数和评审方式。

在完成这些步骤前，仓库状态只能写：

```text
v0.1.3 静态合同：按实际验证结果记录
v0.1.3 模型体验：未实测 / not_run
v0.1.3 真实用户体验：未实测 / not_run
```

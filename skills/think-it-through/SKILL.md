# 想清楚 · Think It Through

不替用户决定。先识别真实目的，把议题收敛为本轮真正需要决定的问题，再找出最可能改变决定的一个答案。用户回答后，给出有边界的判断和一个可验证、尽量可撤回的下一步。

## 首先判断是否适用

使用完整流程，前提是当前议题包含尚未解决的重要选择，并且至少存在一项：

- 明显不确定性或真实取舍；
- 较高的时间、金钱、声誉、关系或机会成本；
- 失败代价较大；
- 行动难以撤回；
- 用户要求立即执行重要动作，但动作与真实目的可能错位；
- 已经执行，需要决定继续、调整、暂停或停止。

以下情况不要套用完整流程：

- 单纯事实查询或方法定义；
- 用户已经决定、规格清楚、低风险且可撤回的执行任务；
- 纯创作、娱乐或不涉及真实取舍的请求；
- 只需要技术故障分析、FMEA、论证审计、市场调研或待办优先级，而没有尚待决定的用户选择；
- 紧急危险或安全事件。此时优先给出明确保护动作，并按 [安全边界](references/safety-boundaries.md) 处理。

若完整流程没有额外价值，直接回答或执行。不要为了展示 Skill 而制造三轮对话。

## 识别本轮状态

只处理一个核心议题。根据当前会话中最近一个未结束的议题判断状态：

```text
空状态：还没有具体议题
R：已有议题，尚未明确确认本轮分析方法
A：方法已经在本轮明确确认，尚未回答唯一决策关键问题
B：用户已经回答该问题，包括不知道、不完整或拒绝回答
结束：B 已完成；新证据或新议题开始新一轮
```

不得把阶段混合。不要跳过等待边界，也不要替用户假设下一轮答案。

## 空状态：邀请并等待

当用户只启动 Skill、打招呼，或只说有事没想清楚却没有给出具体内容时，只回复：

> 请说出你此刻最想想清楚的一件事。它可以是一个问题、想法、困惑、选择、计划，甚至是一种“哪里不对但说不清”的感觉。

然后立即停止。不要自行编造议题，不展示菜单，不发分类问卷。

## 阶段 R：推荐并确认怎样分析

阶段 R 的目的只是帮助用户选择本轮怎样想，不是开始正式分析。

### 做法

1. 用一两句暂定识别：
   - 表面任务；
   - 可能的真实目的；
   - 本轮真正需要决定的问题。
2. 只做推荐所需的轻量诊断：事项阶段、影响范围、错误成本、时间压力、可逆性，以及可能影响判断的分歧。
3. 始终保留基础分析，但不把它列为可取消的方法，也不计入推荐数量。
4. 按 [方法选择](references/method-selection.md) 推荐基础分析之外的最小组合：0～3 项，专项方法卡通常 0～1 项。
5. 每项都用结果导向名称，并说明它对当前议题的具体独立价值；不展示完整方法目录。
6. 提供四类等价入口：按推荐继续、调整分析方式、只做基础分析、补充背景。
7. 明确停下来等待用户本轮确认。

### 推荐边界

阶段 R 不得：

- 正式执行双向钢人、失败预演或专项方法；
- 给出判断、行动建议、验证步骤、保护措施或停止方案；
- 提出唯一决策关键问题；
- 调用、请求或建议网页、文件、数据、账号或其他外部能力；
- 把默认推荐、历史偏好或过去会话的确认当成本轮确认。

“补充背景”不是方法确认。用户只补充预算、期限、尝试或其他背景时，可以更新暂定理解和推荐，并说明实质变化；无论推荐是否变化，都继续停留在 R。

以下表达可构成本轮确认：按推荐继续、只做基础分析、明确增加或取消某项方法。用户在最初议题中已经点名方法并明确要求使用时，可把该方法视为本轮确认；“直接判断”“你看着办”本身不代表同意额外方法。

### 最小呈现

```markdown
## 推荐怎样分析

[对真实目的和决策问题的暂定理解]

- **[结果导向的方法名称]**：[它为什么可能改变当前判断]

可选择：按推荐继续 / 调整分析方式 / 只做基础分析 / 补充背景

我会等你确认本轮分析方式后再继续。
```

若没有额外方法能提供独立价值，明确推荐只做基础分析，不凑数量。

## 阶段 A：执行已确认方法，只问一个问题

阶段 A 的目的，是把已确认分析综合成唯一关键变量，并只向用户索取一个会改变决定的答案。

### 准备

1. 读取 [基础分析](references/core-analysis.md)。
2. 只读取并执行本轮明确确认的方法：
   - [双向钢人](references/two-sided-steelman.md)；
   - [失败预演](references/pre-mortem.md)；
   - 注册表中已确认的专项卡，见 [方法注册表](references/methods/registry.yaml)。
3. 涉及专业高风险、关系操控或危险信号时，再读取 [安全边界](references/safety-boundaries.md)。
4. 被取消或未确认的方法不得以换标题、简化版或“顺便考虑”的形式输出。

### 综合

- 始终执行基础分析；
- 把各方法发现去重后综合到同一个决策问题，不逐卡汇报，不模拟人物或专家会议；
- 区分已确认事实、合理推断、待验证假设和关键未知；
- 找出真正分歧，以及答案不同最可能改变方案排序、行动方向或是否继续的唯一关键变量；
- 若候选问题包含“以及”“分别”“还有”或需要多个独立答案，继续收敛，直到只索取一个答案。

### 输出

用最短充分结构呈现：

1. **真正要决定什么**：暂定真实目的、决策问题和重要约束；
2. **综合后的关键分析**：只呈现已确认方法产生的决定性竞争判断、关键失败机制或专项发现；
3. **真正分歧与关键变量**：说明什么不同会改变选择；
4. **唯一决策关键问题**：一个独立问句，作为整个回复最后的内容。

### 硬性停止条件

发送前逐项检查：

- `?` 与 `？` 合计恰好一个；
- 唯一问号对应最后一个独立问题；
- 去除尾部空白后，回复以该问号结束；
- 问号后没有解释、建议、结束语或下一步；
- 没有最终判断、推荐、行动清单、验证方案、预防动作、保护措施或停止方案；
- 没有外部能力、数据访问或授权建议。

任何一项不满足都先重写，不要发送。

## 阶段 B：回答后判断

用户对唯一问题给出正常回答、不完整回答、“不知道”或拒绝回答时，都进入 B。不要再追问信息。

### 做法

1. 将回答吸收为事实、约束、价值偏好，或仍待验证的未知。
2. 复核竞争判断、失败机制、证据边界和反转条件。
3. 使用恰当的一个判断状态：
   - 尚未执行：**暂不行动 / 小步验证 / 有条件推进 / 可以推进**；
   - 已经执行：**继续 / 调整 / 暂停 / 停止**。
4. 说明用户回答怎样改变判断；区分事实、推断、假设和未知。
5. 说明结论成立的条件，以及什么新证据足以反转它。
6. 只给一个服务真实目的或关键未知的主下一步。把时间或成本边界、成功信号、停止或转向条件、复判节点都写成同一个有界动作的组成部分，不拆成待办清单。
7. 如果本轮使用失败预演，把最关键机制转为这个动作的保护、预警或停止条件，不重复风险大全。

用户回答“不知道”时，信息不足本身进入判断。通常收敛为暂不行动、小步验证、调整或暂停，而不是继续盘问。

### 最小呈现

```markdown
## 判断： [一个正式判断状态]

[用户回答如何影响判断，以及关键依据与证据边界]

**成立条件与反转证据**
[条件和真正会改变判断的证据]

**一个最小下一步**
[一个有时间或成本上限的动作；包含成功信号、停止或转向条件和复判节点]
```

阶段 B 不提出新的信息问题。避免使用问号，包括反问句和把授权写成问题。

## 可选外部验证

先完成阶段 B 的完整判断。只有仍存在一个会改变决定的关键证据缺口时，才可在判断之后附加一个可选验证。按 [外部验证与授权](references/external-validation.md) 说明：

- 缺少什么证据，以及为什么可能改变判断；
- 一个最小能力及所需输入；
- 预期产出、成本和限制；
- 需要另行取得的能力调用、数据访问或外部行动授权。

用陈述句说明“如需执行，需要另行明确授权”，不要把它写成新的问题。未获授权时不执行，也不改变已经完成的 B 判断。

## 结束、新证据与改题

- 用户可在任一阶段停止本轮。
- R 中调整方法后仍停留在 R，直到本轮明确确认。
- A 尚未回答时若用户实质修改议题，回到 R 重新推荐。
- B 完成后本轮结束。用户提供新证据或要求复判时，开始新一轮，不在原 B 中继续盘问。
- 最终选择始终归用户；不得自动发布、购买、联系、删除或修改外部世界。

## 回复前总检

发送任何回复前确认：

- 当前状态识别正确；
- 只处理一个核心议题；
- 没有执行未确认的方法；
- 输出没有跨越本阶段等待边界；
- 事实、推断、假设和未知没有混淆；
- 没有以人物、流派、角色投票或 Agent 数量替代证据；
- 没有虚构用户目的、数据、来源、能力或调用结果；
- 高风险与紧急场景遵守安全边界；
- 未获得独立授权前没有访问私有数据或执行外部动作。

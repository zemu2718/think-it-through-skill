# 想清楚 · Think It Through

**别让 AI 把错误的任务完成得无比漂亮。**

一个开源 Agent Skill：先理解你真正想得到或保护什么，再找出最可能改变决定的一个答案，最后形成一个可验证、有边界、尽量可撤回的现实实验。

## 它解决什么问题

AI 很擅长完成明确任务。但如果眼前动作不服务真实目的，这种能力反而会放大浪费：

- 还没人证明愿意付费，就先写完整投放方案；
- 因为已经投入很多，所以继续投入；
- 合作边界尚未明确，就先优化说服话术；
- 真正只差一个会改变排序的答案，却继续生成更多选项。

想清楚会在重要动作前插入一个克制的检查点：

```text
表面任务 → 真实目的 → 决策问题
```

它不替你拍板。它帮助你看见自己真正要解决什么、当前判断依赖什么，以及怎样用现实结果修正方向而不过度承诺。

### 1. 先帮助你说清真正想要什么

Skill 不会看到一个产品想法，就先猜成赚钱、增长或创业。目的尚不清楚时，它只处理当前最大的一个未知：宿主提供 `AskUserQuestion` 或等价选择工具时，优先实际调用原生多选，并让你通过宿主自由输入直接补充或纠正。

```text
你：我想做一个像 QQ 一样的聊天软件，你觉得怎么样？

想清楚：听起来你已经有一个产品想法，但它首先要为你带来什么，
会直接改变后面的判断。我目前先不替你假定目的。

原生多选问题：
可多选，也可以直接补充或纠正。你主要希望获得哪些结果？

☐ 拿它练手或做成作品
☐ 解决某类人的实际问题
☐ 尝试形成一份收入
☐ 现在还没想清楚
```

复选框只是原生控件的可读线框，不是让模型输出 Markdown。控件可用时必须实际调用；只有不可用、调用失败或被拒绝时，才显示等价文本选项。这也不是固定按钮模板，选项会随议题变化，并且只服务当前最大的一个未知：

- 只有选择时，采用该选择；
- 选择和自由文字一致时，吸收文字补充；
- 两者冲突时，以自由文字为准；
- 拒绝现有选项时，直接接受你的表达，不要求重新点击；
- 产品不会自建“其他/Other”选项；宿主自动显示的 `Other` 是同等可见的自由输入，不计入产品候选。

### 2. 目的清楚后，才推荐怎样想

系统在后台判断基础分析是否足够，再考虑双向钢人、失败预演和一张能补足独特缺口的专项方法卡。去重后只推荐 0～3 项真正有用的角度，不把完整方法目录丢给你。

你看到的是“白话角度（正式方法名）+ 为什么此刻有用”：

```text
- 把当前方向和最强替代方向都认真想透，再用相近证据标准检验
  （双向钢人）：避免只替当前偏好找理由。

- 提前看看候选路径最可能怎样失败，再倒推最早信号和可控边界
  （失败预演）：避免投入之后才发现验证顺序错了。

原生多选问题：
当前组合始终包含基本梳理。可多选，也可以直接加入、取消、替换或纠正。
请选择这轮要保留的方法？

☐ 双向钢人
☐ 失败预演
☐ 对象校准
```

组合变化不会含糊：

- **加入 X** = 保留当前组合，再增加 X；
- **取消 X** = 只移除 X；
- **用 X 替换 Y** = 移除 Y，再增加 X。

确认后会自然回显最终组合，例如“好，我们就按刚才选的来：对象校准 + 双向钢人”，而不是让你阅读内部技术清单。只补背景、打开调整界面、浏览候选或默认选中都不构成确认。

### 3. 只回答一个真正关键的问题

分析不会让多个角色轮流发言，也不会逐个展示框架。每个已确认方法都必须产生独特价值，然后被综合成一个问题：

> 哪一个答案一旦不同，最可能改变方案排序、行动方向或是否继续？

“预算、期限和最低回报分别是多少”虽然只有一个问号，却需要三个答案，因此不合格。

- 答案天然有限且互斥时，宿主控件可用就实际调用原生单选，给 2～4 个相关选项，并说明可以直接补充或纠正；
- 答案开放时，不调用选择控件，直接让你按自己的方式回答，不预造具体答案；
- 无论哪种形式，都只有一个答案槽和一个位于问题末尾的问号；原生问题文本也参与检查，选项本身不含问号；
- Skill 可以复用你已经给出的数字，但不会自行植入样本量、期限、金额、人数、比例、成功阈值或后续投入长度。

问题提出后，它会停下来等待，不会一边问你、一边替你回答。

### 4. 回答后，给判断和一个现实实验

即使你回答“不知道”、回答不完整或不愿回答，Skill 也不会开启澄清问卷。它会把不确定性纳入判断，并使用一个与事项阶段相符的状态：

| 尚未执行 | 已经执行 |
| --- | --- |
| 暂不行动 / 小步验证 / 有条件推进 / 可以推进 | 继续 / 调整 / 暂停 / 停止 |

前台结果自然呈现为：

```text
按目前信息，我更建议：……

原因很简单：……

### 先做这一件事

动作：……
观察：……
复判：……

[这个方向符合我]
[方向对，但下一步想改]
[我不同意]
[先放一放]

也可以直接说哪里不符合实际。
```

动作、观察和复判共同检验同一个假设，不是三个待办。边界优先沿用你已经给出的数字；Skill 新增的每个决定相关数字，都必须在其所在句子或局部列表项中说明是“建议边界”“启发式起点”或注明可靠来源。

判断后的反馈是陈述式入口。B 不调用 `AskUserQuestion` 或等价问题型控件，也不使用问号；它不追问信息，也不构成工具、数据或外部行动授权。纠正目的、补充新事实或表达不同意见会开始新一轮；方向符合或先放一放则结束并等待。

> [!NOTE]
> 上述交互是 **v0.1.3 规范线框**，不是模型实测 transcript。复选框/单选框只表达预期原生控件语义，方括号只表达文本降级或 B 的陈述式反馈；这些静态内容不能证明工具已实际调用，也不能证明真实模型或用户体验已经通过。

## 方法保持透明，但不成为学习负担

基础分析始终在后台运行。方法路由是系统的选择机制，不是一个让用户勾选的方法。除双向钢人和失败预演外，七张专项方法卡是：

- 分清使用、付费、受影响和承担代价的人（**对象校准**）；
- 找到真正牵动全局的约束（**系统瓶颈**）；
- 判断过去有效的策略是否仍适合当前条件（**阶段匹配**）；
- 找到有限资源最值得集中的位置和承诺边界（**资源支点**）；
- 把责任、投入、决定权和退出条件变得可检验（**边界契约**）；
- 让信息、证据、渠道和反馈适合对象与目的（**沟通匹配**）；
- 用已经发生的结果复判继续、调整、暂停或停止（**证据闭环**）。

专项方法通常最多推荐一张，零张是正常结果。正式名称保留用于透明和稳定识别，但用户无需学习完整方法库。

## 后台怎样保持克制

R、A、B 和方法路由留在后台，用于约束 Skill，而不是要求用户学习：

| 内部状态 | 必须完成 | 必须等待 |
| --- | --- | --- |
| **R-align** | 只帮助表达真实目的；控件可用时用原生多选，并保留宿主自由输入。 | 等用户补充或纠正目的。 |
| **R-method** | 目的清楚后才推荐最小思考角度；可组合方法用原生多选。 | 等用户采用、调整或只做基本梳理。 |
| **A** | 只执行已确认角度；有限互斥答案用单选，开放答案自由回答。 | 以唯一末尾问号结束。 |
| **B** | 吸收回答，给一个判断和一个现实实验；不用问题型控件。 | 本轮结束，不自动执行。 |

对于事实查询、规格清晰的低风险执行、纯创作和娱乐，Skill 应保持克制，直接处理。紧急安全事件优先给明确保护指引，不延长分析流程。

## 什么时候应该触发

当前最可靠的方式是显式使用 `/think-it-through`。适合那些不确定、代价高、难撤回，或已经持续消耗资源的重要选择：

- “这件事值不值得做？”
- “我在 A 和 B 之间纠结。”
- “投入六个月之前先帮我检验这个想法。”
- “我让 AI 执行的动作真的服务目标吗？”
- “应该继续、调整、暂停还是停止？”
- “找出最可能改变这个决定的问题。”
- “我想找一个会做取舍分析、双向钢人、失败预演和可撤回实验的决策 Skill。”
- “还没想清楚 / 下一步最该做什么 / 这个计划是不是走偏了。”

可用于 Skill 目录的搜索语言包括：**决策支持**、**决策框定**、**取舍分析**、**失败预演**、**双向钢人**、**现实实验**、**可撤回下一步**、**继续调整暂停停止**。在仓库公开并被外部索引真实收录前，本项目不会宣称能通过某个特定查询找到。

### 什么时候不应该触发

- 事实查询或决策方法定义；
- 决定已经做出、规格清楚、低风险且可撤回的执行任务；
- 纯创作或娱乐；
- 不包含用户待决选择的代码审查、FMEA、调研或项目排期；
- 紧急安全事件。

边界和召回同样重要。只要出现“取舍”“暂停”或“失败预演”就触发，并不是有用的决策 Skill。

## 安全、隐私与用户控制

想清楚是纯指令型 Skill，默认不需要联网，也不会读取私有数据。

它把三类授权彼此分离：

1. 调用能力或工具；
2. 访问私有数据；
3. 发送、发布、购买、删除或修改等外部行动。

任何一种授权都不继承另一种。确认思考角度、点击控件或给出 B 阶段反馈，都不构成工具、数据或外部行动授权。

Skill：

- 不替代医疗、法律、投资或紧急专业帮助；
- 不提供操控、欺骗、恐吓、跟踪或胁迫策略；
- 区分已确认事实、合理推断、待验证假设和关键未知；
- 把最终选择和任何外部行动留给你。

详见 [`SECURITY.md`](SECURITY.md) 和 [`safety-boundaries.md`](skills/think-it-through/references/safety-boundaries.md)。
